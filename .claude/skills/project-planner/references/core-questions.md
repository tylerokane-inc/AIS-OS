# The 10 Core Questions

Ask these at the START of every project, no matter what Tyler is building.
Ask them in **medium batches** (3-4 at a time) using clickable options where it helps.
After each batch, give a short "why" note (1-2 plain sentences) so Tyler learns as he goes.

Do not skip a question. If Tyler answers short, that's fine — capture it and move on.
These 10 answers become the top of the spec doc ("The Big Picture").

---

## The list

**1. What are you building?**
One plain sentence. "A web app that..." / "A dashboard that..." / "A plugin that..."
*Why we ask: a project you can't say in one sentence is a project you don't understand yet.*

**2. Why are you building it?**
The itch. What made you want this? A problem you keep hitting, a thing that's missing, an idea you can't shake.
*Why we ask: the "why" is what keeps you building when it gets hard.*

**3. What is the main goal — what job does it do?**
Finish this: "When it works, it lets someone ______."
*Why we ask: every good product does ONE main job well. This is that job.*

**4. Who is it for?**
You? A specific type of person? A paying customer? Be specific — "busy gym-goers," not "everyone."
*Why we ask: "for everyone" means "for no one." Naming the user shapes every choice later.*

**5. What is the #1 problem it solves?**
The single biggest pain it removes. If it only fixed one thing, what's that thing?
*Why we ask: this is your north star. When choices get hard, pick whatever serves this.*

**6. What does "done and working" look like for version 1?**
Paint the picture of the simplest version you'd be proud to show someone.
*Why we ask: this defines the finish line so v1 doesn't grow forever.*

**7. What are the must-haves vs the nice-to-haves?**
Two short lists. Must = v1 breaks without it. Nice = later.
*Why we ask: this is how we ship fast — build the must-haves, park the rest.*

**8. What's the smallest version you'd actually use yourself?**
Strip it down. What's the tiny core that's still useful?
*Why we ask: the smallest useful version is your real v1. Everything else is v2+.*

**9. What could get in the way?**
Time, money, skills you don't have yet, tools or accounts you'd need, tricky parts.
*Why we ask: naming the roadblocks early means no nasty surprises mid-build.*

**10. How will you know it worked?**
For you: what makes it a win? For others: what shows people actually want it (they use it, share it, pay)?
*Why we ask: without a way to measure "worth continuing," you can't tell progress from busywork.*

---

## After the 10

Once these are answered:
1. Play back a 3-4 sentence summary of the Big Picture so Tyler can confirm or fix it.
2. Ask which build type this is (app / dashboard / plugin / connector / other), then move to `branch-questions.md`.
