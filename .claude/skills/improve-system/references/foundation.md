# Foundation Mode

Goal: review the AIOS's own foundational setup and interview Tyler on what's
genuinely still missing, so future answers (recommendations, plans, drafts)
are grounded in real specifics instead of placeholders.

## Scope

- `context/about-me.md`
- `context/about-business.md`
- `context/priorities.md`

These are the files that already exist for exactly this purpose (filled by
`/onboard`, refreshed any time after). Foundation mode doesn't invent a new
place for "brand, audience, offers" content — `about-business.md` already
holds Offer / ICP / Revenue model / Current stage.

## Process

1. Read all three files as they currently stand.
2. For each section, judge: is this filled with something specific and real,
   or a placeholder/guess/"not yet defined"? List what's genuinely still open.
3. Don't just ask "what's missing" in the abstract — ask specific, answerable
   questions tied to each gap found. E.g. if `about-business.md`'s ICP still
   says "not yet defined further," ask what would sharpen it *right now* (a
   recent conversation, a client conversation, a realization) rather than
   asking Tyler to invent an answer from nothing.
4. If Tyler doesn't have a real answer yet for something, that's a valid
   outcome — leave it marked open rather than filling it with a guess. Per
   `context/about-business.md`'s own convention: "will sharpen once..." is a
   legitimate placeholder, not a gap to force-fill.
5. Draft the proposed edits to whichever of the three files changed, show
   them, wait for confirmation.

## What NOT to do

- Don't re-run the full `/onboard` interview — this is a targeted gap-fill,
  not a from-scratch intake.
- Don't touch `connections.md`, `references/*.md`, or skill files — those
  aren't in scope for this mode (Audit mode covers `references/`; connections
  are their own thing entirely).

## Output format

```
## Foundation review — [date]

### Gaps found
1. [file] — [section] — [what's missing or still placeholder]

### Questions for Tyler
- [specific question tied to gap 1]

### Proposed edits (after Tyler answers)
[exact before/after per file]
```
